# おでんアクアリウム — DECISION FREEZE v1

この文書は、
**現時点で再議論しない前提**を固定するためのもの。

新しい技術的問題・仕様矛盾・重大な事実が発生しない限り、
以下を再設計しない。

---

# 1. Product

おでんアクアリウムは、

**「眺める放置水族館」**

である。

初期フェーズの基本ループ：

1. 開く
2. おでんを見る
3. 昨日より少し染みている
4. 触る
5. かわいい反応を見る
6. 閉じる

育成管理の負担より、
「会いに行く」感覚を優先する。

---

# 2. Penalty

初期フェーズではペナルティを入れない。

以下は実装しない。

- 空腹
- HP
- 死亡
- 放置による罰
- 煮込みすぎによる劣化
- 期限切れ
- ログイン義務

100%は悪化状態ではない。

**最高に染み染みの完成状態。**

---

# 3. State Meaning

ユーザー向け状態：

`soakProgress`

- 0% = 入りたて / 白い / まだ染みていない
- 100% = 染み染み / 黄金色 / 食べ頃

時間経過で0 → 100へ進む。

既存内部 `dashiLevel` が逆方向の場合も、
deriveや保存形式を変更せず、
presentation層で変換する。

---

# 4. Existing Engine

既存の以下は原則維持する。

- deriveはReactから独立した純粋関数
- anchorValue
- anchorTimeMs
- localStorage
- 現在値そのものを保存の中心にしない
- 複数キャラクター前提の保存構造
- 常時setIntervalで進行させない

既存エンジンの再設計を今回の目的にしない。

# 6. Character Direction

食材本来の形を守る。

擬人化は最小限。

基本：

**食材そのもの + 顔 + ごく小さな生物的要素**

避ける：

- 人型化
- 手足を強く人間化
- 衣服主体
- キャラクター化しすぎて食材に見えなくなる造形

Kawaiiは主に、

- 目
- 口
- 頬
- 微細な表情

で作る。

# 7. UI

スマートフォン縦持ち最優先。

基準：

- 390 × 844付近
- 第一級対応：360〜430px

通常画面ではHUDを極力出さない。

理想：

**ゲーム画面ではなく、水槽を覗く画面。**

詳細情報は必要ならタップ時に短時間表示。

debug UIは `?debug=1` に限定してよい。

# 11. AIが停止してよい条件

人間確認が必要なのは原則以下のみ。

1. FIXED仕様変更
2. 保存データ互換性破壊
3. 新しい外部サービス / 有料サービス
4. 新しい本番依存ライブラリ
5. 不可逆操作
6. 技術では決められない大きなArt方向分岐

それ以外で停止しない。

---

# 12. Git / Delivery

AIは原則以下を行ってよい。

- branch
- commit
- push
- PR
- test
- CI修正
- デプロイ

安全条件を満たし、
CIがGreenで仕様差異がなければ、
通常のfeature → main mergeもAI実行可。

人間確認対象：

- force push
- history rewrite
- repository削除
- 大量ファイル削除
- secret変更
- その他不可逆操作
