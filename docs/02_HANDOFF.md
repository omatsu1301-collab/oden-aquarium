## 3. 既存設計で壊してはいけないもの

既存の初期実装仕様における重要な固定事項：

### derive

状態計算ロジックはReactから独立した純粋関数として維持する。

### persistence

永続化の基準は、

- `anchorValue`
- `anchorTimeMs`

とする。

表示用の現在値そのものを永続化の中心にしない。

### characters

現在1体でも、保存データ構造は複数キャラクターを前提とした形を維持する。

### timer

時間経過のために常時 `setInterval` 等で値を書き換え続けない。

「基準値 + 基準時刻」から必要時にderiveする設計を維持する。

## 4. 現在の最大課題

技術基盤ではない。

**ビジュアル品質と世界観の成立**。

現在のプロトタイプは機能確認用としては成功しているが、
理想画像との差が非常に大きい。

今後は、内部エンジンを大きく変更するのではなく、

**見た目の全面刷新 + 必要最小限の表示層追加**

を行う。

## 6. Product方向性

初期フェーズでは、

**育成ゲームより「眺める放置水族館」**

を優先する。

入れないもの：

- 空腹
- HP
- 死亡
- 放置ペナルティ
- 煮込みすぎによる劣化
- 通貨
- ショップ
- デイリータスク
- 広告
- 図鑑
- レアリティ

100%に到達したおでんは、
「染み染みで最高の状態」として維持される。

---

## 7. 状態の意味

ユーザー向け表示概念として、

`soakProgress`

を使う。

- 0% = 入りたて / 白い
- 100% = 染み染み / 黄金色

既存内部値 `dashiLevel` の意味が逆方向の場合も、
既存deriveを壊さずpresentation層で変換する。

---

## 8. UI方針

スマートフォン縦持ち最優先。

基準幅：

- 390 × 844付近
- 第一級対応：360〜430px

通常画面ではHUDを極力出さない。

理想：

**水槽を覗く感覚**

詳細値は必要ならキャラクタータップ時だけ短時間表示。

`?debug=1` では検証用UIを表示してよい。

## 11. AI駆動開発方針

人間はコードを書かない。

AIに原則任せる：

- ファイル構成
- CSS数値
- コンポーネント分割
- アニメーション周期
- レスポンシブ
- 画像圧縮
- lint
- test
- Playwright
- build
- branch
- commit
- push
- PR
- CI
- デプロイ
- 軽微なバグ修正

AIが人間確認で停止してよいのは原則以下のみ。

1. FIXED仕様変更が必要
2. 保存データ互換性を壊す
3. 新しい外部サービス / 有料サービス導入
4. 新しい本番依存ライブラリ追加
5. 公開データ削除など不可逆操作
6. Art North Starから大きく異なる複数案で技術的に優劣を決められない
