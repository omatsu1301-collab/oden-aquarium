## 3. 完成させる体験

水槽で具材が染みる→指で触れてすくう→ポイントと発見記録が増える→商店で出汁/鍋/道具/飾りを購入→使うと水槽や図鑑に反映→お願いの達成と報酬→再訪時に時間が進んでいる。

死亡・腐敗・所持品喪失・図鑑消失・連続ログイン義務はない。出汁がなくても水槽の景色は維持し、具材は半速で育つ。成熟した具材はいつ戻っても成熟したまま。収穫は食べる描写ではなく、おたまで送り出して記録が残る演出。

最初の正式コンテンツは既存5種類。架空の12種類を表示しない。各種類×6出汁の「染め記録」を30通り用意し、同じ種類の出汁違いを新種として水増ししない。これは本実装でのAI決定。

### 4.2 出汁・成長

出汁残量は0〜1の独立した値。基本は満タンから8時間で0。水槽の水位やキャラのsoakとは別物。満タン補充は無料で回数制限なし、進行や成熟をリセットしない。残量25%以下は「少なくなってきたよ」、0は「出汁を足すと、よく染みるよ」。満タンなら補充ボタンは「たっぷり」で無効。

成長倍率 = (残量>0 ? 1 : 0.5) × 装備鍋の速度倍率 × 成長道具倍率 × 時限効果倍率。
保温効果中は残量減少のみ停止。効果期間終了後に減少再開。出汁の種類は速度を変更せず、次回抽選の重みと個体の色/染め記録を変える。

個体は出生時の出汁IDを保持。出汁変更後も既存個体の種類/進行/出汁IDは保持。変更後に収穫して次を抽選するとき新しい出汁を使用。変更だけでは補充しない。この点を商品詳細に短く表示。

### 4.3 正しい経過計算

Reactに依存しない`advanceGame(state, nowMs)`と`applyAction(state, action, nowMs)`を用意。各操作前に時間を精算する。描画ごとのMath.randomやDate.nowへの隠れた依存は禁止。nowとseedは引数/保存状態から渡す。

lastSimulatedAt以降を、時限効果の開始/終了、残量が0になる時刻、スポーン予定時刻で分割し積分する。現在の倍率を過去全時間に掛けない。成熟後は100で止める。長期離席も1秒ごとの巨大ループにせず境界イベントで処理し、最大数十回程度で終了できる構造。

時刻後退時は経過0、基準時刻を後ろへ戻さない。未来時刻へ進められた分はローカルゲームとして許容し、オンライン時刻検証は追加しない。時刻が追い付くまで停止する挙動をテスト。タイマーは表示更新のため可視時に1秒程度で共通1本のみ、差分加算を正しさの根拠にしない。非表示時は止め、復帰時に精算。毎秒localStorageへ書かない。

### 4.4 収穫操作

成熟個体はタップ/キーボードEnter・Spaceで収穫。未成熟は従来のかわいい反応と短い名前/進行表示。水槽のキャラ領域をなぞって成熟個体を連続収穫できる。UIボタン・パネル上では発火しない。同じpointer操作中の同一個体を重複収穫しない。アニメ終了を待って報酬処理する方式は禁止。データ処理を先に一度だけ確定し、描画上の残像で演出。

報酬・図鑑・統計・次の個体予約は1トランザクション。新種は小さな「図鑑に新しい仲間」通知（押すと詳細）。初回染め記録も保存。スクロール誤操作防止としてtouch-action:noneは水槽の収穫領域だけに限定。

## 6. 7画面のUI契約

### 6.1 共通

主画面は水槽/図鑑/商店。hashルーティング又は同等の軽量実装でPagesの直リンクと戻る操作を保証。ルータ追加は必須でない。各主画面のスクロール/タブを維持。最下部に図鑑｜水槽｜商店、主画面の選択状態を示す。パネルは共通Sheet、閉じる/Escape/背景タップで戻る。ブラウザ戻るはまずパネルを閉じる。商品の再選択等で際限なくhistoryを積まない。

Sheetは一枚だけ表示し、入れ子の器選択/商品確認は内部ページ切替と戻るで実装可。role=dialog/aria-modal、フォーカス移動と復帰、背景inert、スクロールロック。見出し/閉じるを固定し内容のみスクロール。画像の固定割合を強制せず、360×640でも末尾操作へ到達可能。ドラッグ閉じはハンドルだけ任意実装、内容スクロールと競合させない。

基準390×844、360〜430px優先、320pxでも破綻なし。desktopは最大幅480px程度の中央レイアウト、外側に落ち着いた背景。100dvhとsafe-areaを考慮。文字は本文14〜16px目安、操作44px以上。画面全体のtransform縮小で対応しない。夜背景上の文字は明るい面か十分な白文字コントラスト。装飾はpointer-events:none。実装用CSS変数に色/余白/角丸/影を集約。

### 6.8 設定

05構成。BGM0〜100%、効果音0〜100%、振動、動き低減、JSONバックアップ、復元、遊び方、クレジットを全実装。既定BGM40/SE70/振動on、動き低減は初回OS設定に合わせ以後ユーザー設定を保存。

音はWeb AudioでAIが短い穏やかなオリジナル環境音/BGMと操作音を実装してよい。初回ユーザー操作後だけAudioContextを開始。非表示で停止/復帰時に再開可能、音量0で無音、ノード多重起動やループのクリック音を防ぐ。外部有料音源なし。振動API非対応は項目に「この端末では利用できません」、例外なく進行。動き低減で浮遊/泡/光/Sheet移動/収穫の大きな動きを抑え、状態変化は残す。

遊び方は実際の操作・出汁が0でも消えない・ポイント・商店・保存が端末ブラウザ単位であることを短く説明。クレジットは実際の作者/使用技術/素材方針/ライセンスだけ。個人名や所有権を捏造しない。

## 7. 保存・復元・互換性（最重要）

### 7.1 v2の構造

保存値例：schemaVersion:2、revision、lastSimulatedAt、rngState、nextInstanceId、wallet、tank{brothId,remainingRatio,potId,tools,decorationId}、slots[{slotId,instanceId,speciesId,brothId,spawnAt,progress,duplicateStreak}]、catalog{speciesId:{firstSeenAt,harvestCount,favorite,bowlId,brothCounts}}、inventory{ownedIds,consumables}、effects{growth,care}、stats{harvestTotal,brothsUsed,customBowlApplied}、claimedQuestIds、lettersRead、settings。名称は整理してよいが情報を欠かさない。表示上のSheet/トーストは永続化しない。

Date.nowはclock adapter、乱数は保存seedを更新する純粋関数。IDは永続カウンタ等で復元後も衝突しない。ロジック/保存/見た目は分離。reducer内で保存や音を直接実行せず、単一storeのdispatch経路で副作用を管理する。

### 7.2 v1→v2移行

旧キーを読む前にv1対応を残す。旧raw文字列を`oden-aquarium/save-v1-backup`へ一度だけ退避できたことを確認し、それから移行。退避失敗時に旧rawを上書きしない。

v1の大根は旧式（2ポイント/時）で移行時点まで導出した値を0〜100へclampし、最初の大根個体へ引き継ぐ。旧経過へ新速度を遡及適用しない。他4体は新規の75/50/25/0。300pt等は新規と同じ。旧版には収穫履歴がないため、発見日や収穫数を捏造しない。初回の大根100%ボーナスは移行個体に上書きしない。v2保存成功後は再移行/初期特典再付与しない。旧純粋関数をmigration用に残せば既存verifyを維持しやすい。

schema未知/不正JSONは自動初期化して上書きしない。原文保持、読み込みエラーとJSON退避/バックアップ復元の入口を示す。明示的に新しく始める場合だけ別途確認して初期化。通常設定に常駐の削除ボタンは不要。

### 7.3 書込と複数タブ

状態変更ごとに検証して保存。書込失敗時は「この端末に保存できません。バックアップしてください」と明示し、成功表示を出さない。メモリ上の状態は維持してJSON出力可。pagehide/visibilitychangeでも可能な範囲で精算/保存するが、それだけに依存しない。

複数タブの買い物/収穫の競合を防ぐ。Web Locksが利用可能なら短い排他処理内で最新revision再読込→精算→操作→保存。storageイベント/BroadcastChannelで反映。非対応時は単一アクティブタブ方式のleaseと期限/復帰処理を採用し、他タブに閲覧状態と再取得案内。localStorageのread-modify-writeだけを原子的と誤認しない。インポートも同じ排他経路。

### 7.4 JSONバックアップ/復元

Blobで`oden-aquarium-backup-YYYYMMDD-HHmm.json`をダウンロード。内容はapp識別子/formatVersion/exportedAt/gameState。ダウンロード開始を成功保存と混同しない。復元はファイル選択→最大1MBと型/範囲/既知ID/finite数/重複ID/参照整合/schemaを検証→内容要約→「現在の記録を置き換える」確認→現在状態の退避成功→置換。キャンセル/不正/未知版/書込失敗で現在データを消さない。外部JSONをObject.assignで無制限に混ぜず、許可fieldから正規化。未来版の自動ダウングレード禁止。v1形式インポートも上記移行を通す。

## 9. 検証と完了条件

### 単体/統合テスト（fake clockとseedで再現）

- 全商品参照/全お願いが到達可能。価格/名称/効果が単一データ定義由来。

### ブラウザ操作

Playwright等で：初回大根収穫→図鑑詳細→お気に入り→商店でかつお購入/使用→お世話補充/アイテム→時間送り→収穫→お願い報酬→設定→再読み込み維持→バックアップ/復元。全5商店タブを押し、全商品の購入/適用先をdebug用テストで網羅。おたより既読化も確認。

debugは本番通常URLに出さない。時間送り/リッチな状態/全所持のfixtureは`?debug=1`かdev専用、通常保存と別キー/別storeを用い、復帰時に本番データを汚染しない。テストのために通常の初期残高を増やさない。

390×844で7画面のスクリーンショットを保存。360×640、430×932、desktopでも一覧末尾、Sheet末尾、ナビ、safe-area、テキストはみ出しを確認。図鑑詳細の背後が夜、商店も夜、水槽は元の黄金色。パネル開閉で具材位置が変わらない。キーボード操作/Escape/フォーカス復帰/ブラウザ戻る/低減モードを確認。非対応振動は実機確認済みと偽らない。

`npm run verify:derive`、追加テスト、`npm run lint`、`npm run build`を通す。既存verifyの成功を壊す場合は仕様更新による変更を説明し、移行用旧計算の回帰テストを残す。テストを削除・skipして緑にしない。

本番baseでビルドpreviewし、素材404/console errorを確認。実機を触れない場合はその項目だけ未実施と明記し、ブラウザ検証を実機確認済みと称しない。

### 完了の定義

## 10. Git・公開・報告

既存`docs/04_DECISION_FREEZE.md`には、通常branch/commit/push/PR/CI修正/条件付きmerge・deployの許可がある。現状の権限と上位指示を確認して、この許可の範囲で実行。従来のArt Gateを今回の各画面ごとに再要求しない。新しい課金サービス、秘密情報変更、履歴書換え、破壊的データ移行は実施しない。

PR作成前にdiffをレビューし無関係ファイル/秘密情報/セーブデータを含めない。PR本文は問題、変更、検証、保存移行、制限を明記。証拠画像は実際の添付先を正確に記載。ローカルに置いただけで「PRに添付済み」と書かない。
