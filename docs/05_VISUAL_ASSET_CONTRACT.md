# おでんアクアリウム — VISUAL ASSET CONTRACT v1

## 目的

AI生成アセットの一貫性を保ち、
後工程での作り直しを最小化する。

全画像生成・画像編集・Web実装はこの契約を基準にする。

---

# 1. Art North Star

基準画像：

`おでんアクアリウム イメージ図.png`

この画像の完全コピーではなく、
以下の性質を守る。

- 黄金色のお出汁
- 水中
- 暖かな光
- 柔らかい絵画的質感
- Cozy
- 幻想的
- 食べ物として認識できるキャラクター
- 控えめな擬人化
- 多数の小さな泡
- 奥行きのある水槽

---

# 2. Background Contract

背景アセット：

`aquarium-background.webp`

条件：

- 縦長スマートフォン構図
- キャラクターを焼き込まない
- 読ませる必要のある文字を焼き込まない
- 中央付近にキャラクター配置用の安全領域を確保
- 上部に水面 / 光源を感じる構図
- 下部に岩・砂等の奥行きを感じさせる
- 左右に多少の海藻・環境物があってよい
- 主役はキャラクターなので背景の情報密度を上げすぎない

推奨：

- WebP
- 高解像度マスターを生成し、Web用に圧縮
- 390×844周辺でトリミングしても主要構図が壊れない

---

# 3. Character Contract

キャラクターアセット：

- `daikon.png`
- `chikuwa.png`
- `shirataki.png`
- `konnyaku.png`
- `ganmo.png`

条件：

- 透明背景PNG
- 食材本来の形状を優先
- 目 / 口 / 頬を中心に最小限擬人化
- 人型にしない
- 同一光源
- 同一画風
- 同程度の線密度
- 同程度の彩度
- 背景に置いた時に切り抜き感が強く出ない
- キャラ単体で影や発光を焼き込みすぎない
- Web側で位置・影・浮遊を調整できる余地を残す

---

# 4. Character Style

## 大根

- 円柱〜輪切り感
- 白〜淡いクリーム
- 柔らかい輪郭
- 断面の繊維感は控えめ
- 顔は小さめ
- 全体は穏やか

## ちくわ

- 細長い筒
- 穴が明確
- 焼き色
- 大根とは大きく異なるシルエット
- 同じ世界観に見えることを優先

---

# 5. State Variation Contract

状態差分を別々の新規生成として作らない。

原則：

`master image`
↓
image edit
↓
`soaked image`

大根例：

- `daikon-master.png`
- `daikon-soaked.png`

0 / 25 / 50 / 75 / 100 の5枚を最初から作らない。

まずは：

- 1枚 + CSS色変化

で検証。

不足する場合のみ：

- normal
- soaked

の2画像方式へ進む。

---

# 6. Soak Visual Direction

`soakProgress`

### 0%

- 白
- 透明感
- 淡いクリーム
- 出汁色は弱い

### 50%

- 淡い黄金
- 少し温かい色
- 出汁が内部に染みた印象

### 100%

- 黄金色
- 艶
- ほんのり暖かいハイライト
- 焼けた色ではなく「染みた色」
- 汚れ / 劣化 / 腐敗表現は禁止

---

# 7. Text Contract

重要テキストを画像に焼き込まない。

画像生成AIによる日本語文字は、
装飾としても原則使わない。

必要な文字は：

- HTML
- CSS
- 別SVG

で実装する。

Art North Star内の看板文字は
世界観参考として扱い、直接再現を必須としない。

---

# 8. Effects Contract

初期実装：

- 泡：CSS
- 光：CSS overlay
- 浮遊：CSS animation
- 微細な水中揺らぎ：CSS

Canvas / WebGLは使わない。

画像に泡を大量に焼き込む場合でも、
動く泡用の空間を残す。

---

# 9. Asset Generation Workflow

最初に生成するのは3素材のみ。

1. `aquarium-background.webp`
2. `daikon.png`
3. `chikuwa.png`

ここでGate Aを通過するまで、
しらたき・こんにゃく・がんもを生成しない。

---

# 10. Candidate Policy

1キャラクターにつき複数候補を出す場合、
人間は原則：

- A
- B
- C
- D

から採用候補だけ選ぶ。

微修正は採用候補を元にimage editする。

ゼロから何度も生成し直して
スタイルを漂流させない。

---

# 11. Rejection Criteria

以下は不採用。

- キャラクターだけ別作品に見える
- 背景との光源が矛盾
- キャラクターが人型すぎる
- 食材として認識しにくい
- 線画アニメ風と絵画背景が強く衝突
- 過度に3Dレンダー的
- 写実的すぎる
- 過度に幼児向け
- 水中より「黄色い背景」に見える
- 背景へ重要文字が焼き込まれている
- 同一キャラ状態差分で輪郭・目・口がズレる

---

# 12. Success Criterion

成功とは、

**個別に生成した背景とキャラクターを合成しても、
最初から一枚絵として描かれたように見えること。**

技術的に正しく切り抜けているだけでは不十分。
